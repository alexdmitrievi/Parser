# Политика скрапинга

Правила обязательны для **всех** доменов проекта — `tenders`, `funding`,
`leads` и любых будущих. Изначально они были сформулированы владельцем для
домена `leads`; этот документ распространяет их на весь проект.

Это не рекомендации. Изменение любого пункта — решение владельца проекта, а не
разработчика или агента.

---

## 1. Обязательные правила

1. **Уважать `robots.txt`.** Запрещённые пути не запрашивать. Реализация —
   `engine/fetchers/robots.py`, режим fail-closed: если `robots.txt` не
   удалось получить, считаем, что доступ запрещён.
2. **Вежливый режим.** Задержка между запросами не меньше настроенной,
   конкурентность не выше 2, честный `User-Agent` с реальной контактной почтой.
3. **Не обходить антибот-защиту.** Никакой подмены отпечатков, никакой
   эмуляции браузера ради обхода, никакого решения капчи. Для доменов
   `tenders`/`funding` это ограничение снято решением владельца — см. §2.
4. **Только публичные страницы.** Никакой авторизации, никаких закрытых
   разделов, никакого доступа под чужой учётной записью.
5. **Уважать `Retry-After` и код 429.** Ответ 403 или 429 — сигнал
   остановиться, а не повод сменить адрес и повторить.
6. **Персональные данные.** По умолчанию собираются только ролевые адреса
   (`info@`, `sales@`, `export@`). Именные — только по явному флагу и с
   предупреждением о правовых рисках в документации.

---

## 2. Где проходит граница по прокси

Пункт 3 запрещает обход антибот-защиты. **Решением владельца (2026-09) для
доменов `tenders` и `funding` это ограничение снято: «ничего не под запретом»** —
прокси-ротация и сервисы вида ScrapingBee допустимы для площадок, которые
блокируют сбор адресно. Для домена `leads` запрет сохраняется полностью.

Различаем два случая — они определяют `access_mode` источника:

**`geo` — легальная точка выхода.** Площадка не блокирует конкретно нас, а
просто не обслуживает адреса за пределами страны. Российский VPS для доступа
к `zakupki.gov.ru` — это выбор места, откуда мы ходим, а не обход защиты.

**`proxy` — обход антибота (допустимо по решению владельца).** Площадка
выставила блокировку намеренно и адресно: капча, 403 с превышением лимита,
антибот-фингерпринт датацентровых диапазонов (например `b2b-center.ru`,
`rts-tender.ru`). Здесь используется прокси/ScrapingBee.

**Практическое правило.** Прежде чем пустить источник через прокси, определите,
к какому из двух случаев он относится, и запишите это в `access_mode`
конфигурации источника. Если по признакам непонятно — спросите владельца.

Отдельно: в домене `leads` прокси и ротация `User-Agent` запрещены полностью.
Там используется `PoliteFetcher`, а не `HttpFetcher`. Это сильнее общего
правила и остаётся в силе.

**Исключение (решение владельца, 2026-09): Firecrawl для all.biz.** Каталог
`all.biz` сидит за Cloudflare и адресно отдаёт 403 датацентровым диапазонам
(проверено: Яндекс.Облако и Azure/GitHub Actions). Для него разрешён **только**
управляемый сервис Firecrawl — рендер JS с чистых IP, без подмены `User-Agent`
и без капча-солверов. Включается точечно: `FIRECRAWL_API_KEY` +
`LEADS_FIRECRAWL_SOURCES=allbiz`. Реализация — `FirecrawlFetcher`
(`engine/fetchers/firecrawl_fetcher.py`). Прокси-ротация и подмена `User-Agent`
в домене `leads` по-прежнему запрещены.

## 3. Режимы персональных данных по гео

Проект работает с несколькими юрисдикциями. Ограничения закладываются **в код**,
а не только в документацию.

| Гео | Режим | Что это значит на практике |
|---|---|---|
| КНР | PIPL | по умолчанию только ролевые адреса; именные — по явному флагу |
| ЕС | GDPR | законное основание обработки нужно до сбора, а не после |
| РФ | 152-ФЗ | требования к обработке и хранению персональных данных |

Перед запуском сбора в новом гео определите применимый режим и заложите
ограничение в конфигурацию источника.

---

## 4. Что должен уметь код, чтобы соответствовать политике

- Гейт `robots.txt` перед запросом, с кешем и учётом `Crawl-delay`.
- Настраиваемая задержка с нижней границей, которую нельзя обойти конфигом.
- Ограничитель конкурентности.
- `User-Agent` с контактом; отсутствие настроенного контакта — ошибка запуска,
  а не значение по умолчанию. Так уже сделано в `parse-leads.yml`: workflow
  падает, если `LEADS_CONTACT_EMAIL` пуст или равен заглушке.
- Обработка `Retry-After`, 429 и 403 как сигналов остановки.
- Классификация адресов на ролевые и именные до записи в хранилище.

---

## 5. Проверка

Правила покрываются тестами, а не только ревью. При добавлении источника или
домена убедитесь, что есть тест на:

- отказ от запроса запрещённого в `robots.txt` пути;
- соблюдение минимальной задержки;
- остановку по 429 и по `Retry-After`;
- фильтрацию именных адресов при выключенном флаге.

Существующие тесты домена `leads` — `engine/tests/leads/` — годятся как образец.
